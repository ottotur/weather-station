# Domain docs

## Layout

Single-context: root `CONTEXT.md` and `docs/adr/`.

## Before exploring

Read `CONTEXT.md` and ADRs relevant to the area being investigated.

If these files do not exist, proceed silently. Create them through
domain-modeling only when terminology or decisions have been resolved.

## Vocabulary

Use domain terms as defined in `CONTEXT.md` in issues, designs and code.
Flag missing or conflicting terminology for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, citing the relevant ADR.
Treat a proposal to reopen a decision separately from an approved change.
